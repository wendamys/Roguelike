# 🎮 Регламент работы с Git и ветками в проекте Roguelike

Привет, команда! Мы настроили чистую структуру проекта на **Gradle + Lanterna** и включили строгую защиту веток на GitHub. Прямой пуш в ветки `main` и `develop` **заблокирован**. Все изменения вносятся строго по правилам ниже.

---

## 🛠 1. Первый запуск проекта (Для тех, кто только подключается)

Если вы еще не скачали проект к себе на компьютер:
1. Откройте IntelliJ IDEA. На стартовом экране нажмите **Get from Version Control**.
2. Вставьте ссылку на наш репозиторий GitHub и выберите папку на диске.
3. Нажмите **Open**. Среда разработки через *Gradle Wrapper* сама скачает нужную **JDK 21** и библиотеку **Lanterna**. Вам ничего дополнительно настраивать не нужно.

---

## 🌿 2. Создание своей ветки под задачу

Мы работаем по системе **Git Flow**:
* `main` — только готовая, стабильная игра (релиз).
* `develop` — главная рабочая ветка, куда все сливают свои задачи.
* Ваша личная ветка — создается для выполнения конкретной задачи (фичи).

### Шаг 1. Обновите локальный `develop`
Перед тем как начать писать код, обязательно скачайте то, что уже успели написать другие участники команды:
```bash
git switch develop
git pull origin develop
```

### Шаг 2. Создайте свою ветку от `develop`
Название ветки пишем в формате: `feature/ваше-имя-короткое-описание`.
```bash
git checkout -b feature/ivan-map-generation
```
*(Команда `checkout -b` создаст новую ветку и сразу переключит вас на нее).*

---

## 💻 3. Написание кода и проверка (Локально)

Вы пишете код, переносите свои папки в структуру `src/main/java/` и тестируете проект.

### Как запустить игру для проверки?
В правой части экрана IntelliJ IDEA найдите вкладку **Gradle** (значок слоника) и запустите задачу:
👉 **`Rogue -> Tasks -> application -> run`** (дважды кликните по `run`).
Lanterna откроет эмулятор терминала. Если всё работает без ошибок, можно сохранять код.

---

## 🚀 4. Заливка кода на GitHub (Push)

Когда задача готова и протестирована на вашем компьютере, отправляем её в облако:

```bash
# 1. Посмотрите, какие файлы вы изменили/добавили
git status

# 2. Добавьте все изменения в индекс
git add .

# 3. Сделайте коммит с понятным описанием
git commit -m "Добавил алгоритм генерации комнат и отрисовку стен"

# 4. Отправьте ветку на GitHub (флаг -u нужен только при самом первом пуше ветки)
git push -u origin feature/ivan-map-generation
```

---

## 👀 5. Проверка кода и слияние (Pull Request & Code Review)

Теперь ваша задача должна попасть в общую ветку `develop`.

1. Зайдите на наш репозиторий на сайте **GitHub**.
2. Вверху вы увидите желтую плашку с вашей веткой. Нажмите кнопку **Compare & pull request**.
3. Настройте направление слияния (это самый важный пункт!):
    * **base:** `develop` 👈 *(куда вливаем)*
    * **compare:** `feature/ivan-map-generation` 👈 *(ваша ветка)*
4. Напишите кратко, что было сделано, и нажмите **Create pull request**.
5. **Код-ревью:** Ссылка на Pull Request скидывается в чат команды. Хотя бы один сокомандник должен зайти во вкладку *Files changed*, посмотреть код и нажать кнопку **Approve** (Одобрить). Без этого кнопка слияния будет заблокирована.
6. После одобрения нажмите зеленую кнопку **Merge pull request**. Ваша задача официально добавлена в общий проект!

---

## 🔄 6. Синхронизация (Что делать остальным?)

Когда чей-то Pull Request был успешно влит в `develop`, всем остальным участникам команды нужно обновить свои рабочие места, чтобы не возникло конфликтов кода.

Если вы сейчас находитесь в процессе написания своей фичи, сделайте следующее:
```bash
# 1. Переключитесь на локальный develop и заберите код коллеги с сервера
git checkout develop
git pull origin develop

# 2. Вернитесь в свою личную рабочую ветку
git checkout feature/ваша-текущая-ветка

# 3. Влейте свежий общий код в свою ветку
git merge develop
```
Если возникнут конфликты (когда два человека правили одну и ту же строчку), IntelliJ IDEA откроет удобное окно с тремя панелями. Там нужно будет просто выбрать мышкой, какую версию кода оставить — вашу или коллеги.

---

### 💡 Короткая памятка на каждый день:
* Пишем код **только** в ветках `feature/...`
* Pull Request делаем **строго в ветку `develop`**
* Перед началом работы всегда делаем **`git pull origin develop`**
