# GameFacade Implementation Plan

## Context

В проекте уже есть слоистая архитектура:
- **`domain/gameSession/Game.java`** — центральный класс игры с полной логикой
- **`presentation/Main.java`** — точка входа (пока без Controller)
- **`datalayer/`** — слой persistence с DTO

Game класс сейчас:
- Зависит от `System.in` / `System.out` для ввода-вывода
- Содержит полный игровой цикл (game loop)
- Имеет много public методов для доступа к внутреннему состоянию
- **Не имеет чёткого API** для внешних контроллеров

---

## Цель GameFacade

Создать **фасад** — упрощённый интерфейс, который:
1. Скрывает сложность Game и его зависимостей
2. Предоставляет понятные методы для Controller
3. Позволяет легко заменить Game без влияния на Controller
4. Подготавливает архитектуру для тестирования (Mocking)

---

## Рекомендуемая реализация

### 1. Создать интерфейс `GameFacade`

**Файл**: `src/main/java/domain/gameSession/GameFacade.java`

```java
package domain.gameSession;

import domain.backpack.Backpack;
import domain.characters.Player;
import domain.map.DungeonGenerator;
import domain.map.Position;
import domain.navigator.DirectionType;

import java.util.List;

public interface GameFacade {
    // Game state
    boolean isGameEnded();
    void setGameEnded(boolean ended);
    
    // Access to core components
    Player getPlayer();
    Backpack getBackpack();
    DungeonGenerator getGenerator();
    
    // Movement
    void movePlayer(DirectionType direction);
    
    // Inventory
    void useItem(int index, ItemsType type);
    void selectInventoryType(ItemsType type);
    
    // Game control
    void startGame();
    void nextLevel();
    
    // Query methods
    List<Enemies> getAllEnemies();
    List<Item> getAllItems();
    Position getLevelPosition();
}
```

### 4. (Опционально) Упростить Game

После создания фасада можно:
- Сделать методы `handleInput`, `start` приватными в Game
- Вынести консольный ввод-вывод из Game (для лучшего тестирования)
- Создать `GameFacadeConsole` — реализацию для консольного интерфейса

## Преимущества

1. **松耦合 (Slabaya zvyazanayac)** — Game и Controller слабо связаны
2. **Тестируемость** — можно замокать GameFacade в тестах
3. **Гибкость** — легко создать разные реализации (Console, Network, Test)
4. **Простота** — Controller работает с понятным API, а не со всей сложностью Game
